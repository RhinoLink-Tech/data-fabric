# 飞书多维表格只读数据源：候选方案评估

[English](feishu-bitable-evaluation.md)

状态：**方案候选，尚未实现**。跟踪：[#755](https://github.com/RhinoLink-Tech/data-fabric/issues/755)。目标是查询业务数据，不是做 ELT 数据搬运。目前没有该候选的真实客户需求、飞书凭证、线上 API、WorkBuddy 或跨源查询验收证据。

## 一个实际场景

假设销售运营人员想统计本周销售线索的状态，并查看待跟进线索的前两页。合成表只允许 `record_id`、`status`、`created_at`，不含姓名、电话和备注。人工基线是假设运营人员筛选多维表格视图、统计状态并复制结果；这不是实测流程。真实团队需确认负责人、表格和筛选条件、时区、人工耗时及验收标准。

## 路线选择

先用本地模拟服务验证**轻量只读 HTTP 适配器**，让单源场景不必额外部署 Trino；取得真实任务及授权测试环境后再验证真实 API。此阶段不宣称支持 SQL 或跨源。

| 方案 | 优点 | 成本与待验证事项 |
| --- | --- | --- |
| 网关直连 API | 单源部署简单；经明确接入和测试后可复用网关身份、授权、审计及资源预算。 | 需实现源端身份、字段映射、分页和查询语义。当前原生 API 查询游标通过偏移量和 count SQL 重新请求，不能直接等同于服务端不透明分页令牌。首个验证应限定为记录读取，不冒充通用 SQL。 |
| Trino 连接器 | 已验证的连接器将来可能利用联邦引擎实现跨源关联。 | [Trino 484 内置列表](https://trino.io/docs/current/connector.html)没有飞书多维表格；未评估第三方实现。自行开发需要[元数据、分片、页面读取等插件组件](https://trino.io/docs/current/develop/connectors.html)，还需部署 Trino 和插件，并独立验证权限、身份、只读、时效、限额和跨源关联。 |

两条路线都要明确飞书调用身份、表格/视图及字段权限，并仅申请目标 API 所需权限；凭证不得进入 Skill、模型对话、日志或结果。[飞书权限说明](https://open.feishu.cn/document/base-extensions/base-table-view-extension-development-guide)在扩展场景列出了多维表格只读权限，但服务端目标 API 所需权限与用户/应用身份仍须单独核对。[令牌刷新文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/refresh-user-access-token-v3)介绍了刷新流程，不能假设所有部署都具备刷新权限或令牌永久有效。

[飞书常见问题](https://open.feishu.cn/document/docs/bitable-v1/faq?lang=zh-CN)说明高级权限可能影响返回数据，空字段可能不出现在结果中。空结果本身不能证明用户有完整权限，也不能证明业务数据确实为零。

## 最小验证与验收

1. 本地模拟 HTTP 服务提供固定合成数据和不透明分页令牌；检查字段、至少两页、空值、失效令牌、权限拒绝、限流、超时、取消和分页期间数据变化。日志与响应不得泄露密钥。
2. 分页状态绑定调用者、租户、数据源、查询和有效期，限制页数、行数、字节数及总时长；清楚报告错误、截断和不完整结果。源端变化时不假定分页具有快照一致性；不暴露写入。
3. 定义标量字段和时间的安全映射，拒绝不支持或含糊的值。只有相关页在预算内全部读取后才能给出完整统计；SQL 聚合、条件下推和跨源关联须实现并通过网关授权、审计的端到端验证后才能宣传。
4. 接真实飞书前，确认任务、授权表和字段、测试身份及同意、源账号负责人、网络出口、合成数据与清理方式；记录实际 API、权限与限流。费用、配额和数据时效以实际飞书套餐与接口文档为准，不预设价格或快照保证。
5. 面向 MCP 发布前，使用实际发布的服务和目标 WorkBuddy 版本复测权限拒绝、撤销授权、分页及客户端展示，再公开记录范围和结果。

模拟服务可在进程内运行，不需要下载容器镜像。此评估不等于真实 API 或客户端验收。外部文档可能变化，实现时应重新核对。
