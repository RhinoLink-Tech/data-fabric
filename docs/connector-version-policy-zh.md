# 数据源版本与支持策略

[English](connector-version-policy.md) · [当前支持目录](data-source-support.md) · [驱动契约证据](driver-contract-tests.md)

这份说明帮助使用者判断某个数据源、版本和操作是否适合自己的部署。它说明的是验证证据和维护方式，不代表生产 SLA，也不自动承诺覆盖数据库厂商的整个产品生命周期。

## 如何判断当前版本

1. 确认实际运行的 Data Fabric 发布版本或镜像摘要；其他源码版本生成的目录可能不同。
2. 从 `/api/v1/database/types` 查询准确的数据源类型，或使用 MCP `list_source_types`，指定 `type` 和 `include_details: true`。同时查看版本策略、操作、认证说明和限制。
3. 将实际数据库产品及精确版本与 `verifiedServerVersions`（MCP 中为 `verified_server_versions`）比较。版本探测是尽力而为；无法识别时表示未知。
4. 使用前检查对应认证、TLS、查询和拓扑是否有证据。连接测试成功本身不等于通过完整契约验证。

| 情况 | 识别方式 | 含义 |
| --- | --- | --- |
| 精确版本已验证 | 端到端验证字段为 true，且实际产品和版本在已验证列表中 | 对记录的镜像和场景通过契约测试，不代表覆盖所有配置与操作。 |
| 已声明支持范围 | 非空的支持范围与版本策略明确声明连续范围 | 仅适用于所写明的产品、环境和操作；带 `only` 的版本枚举不是连续范围。 |
| 尚未验证 | 实际版本没有对应证据，或无法识别版本 | 兼容性未知；服务可能允许尝试，但不能据此断定一定可用或不可用。 |
| 明确不支持 | 状态为 `unsupported`，或限制说明拒绝了对应操作/配置 | 不应将该操作展示为可用；按说明选择其他支持路径。 |

`status` 描述整个连接器状态，并不是每一个版本的结论。受限的实验性适配器也可能有某个版本的端到端证据。REST 中兼容旧客户端的 `supported` 字段表示驱动已注册，并不等于支持承诺；`registered` 或 `implementation_present` 也不能证明连接可用。

## MySQL 与 PostgreSQL 样板

具体版本和验证范围以[生成的支持目录](data-source-support.md)与[固定版本契约报告](driver-contract-tests.md#verified-baselines)为准。例如，目录记录了 PostgreSQL 17.11 和 MySQL 8.4.13 等精确版本；前者有 `verify-full` TLS 契约，后者覆盖可信 CA 和主机名校验。这些是证据示例，不表示整个 17.x 或 8.4.x 已受支持。

未来可优先评估 PostgreSQL 15–18 和 MySQL 8.0/8.4 版本族，因为现有矩阵中已有其中的精确版本。**这不是已声明的支持范围。** 在发布连续范围前，维护者需要确定版本端点、认证和操作范围，运行约定的可重复矩阵，分析失败并写明剩余限制；少数补丁版本通过不能证明整个版本族。测试可以在 CI 或已批准的现有环境执行，本策略不要求在本机拉取镜像。

## 证据更新与退出支持

- 连接器维护者提交版本或范围变更时，记录源码版本、Data Fabric 制品、数据库产品及版本、固定的测试制品、操作和认证/TLS/拓扑范围，并关联可复现的成功与失败结果。跳过不算通过；不记录凭据和真实数据。
- 维护者审核证据后，同步更新运行时目录、生成文档、契约报告和发布说明。某个来源的状态应由它自己的证据决定。
- 数据库厂商的维护结束公告触发项目维护者评估，不会自动改变 Data Fabric 的支持状态或期限。做出决定后，在目录和发布说明中记录日期、迁移路径及替代证据；项目尚未公布决定时，不承诺支持窗口或退出日期。
- 发现回归或证据失效时，明确受影响的范围和操作，保留历史记录并给出可执行的替代方案。

新增验证时，参照[驱动契约测试](driver-contract-tests.md)，使用隔离合成数据并记录成功、失败和跳过情况。单个连接器兼容性不能替代整个发布版本的安装、升级和恢复验收。
