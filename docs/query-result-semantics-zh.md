# 查询结果语义

English: [Query result semantics](query-result-semantics.md).

本文说明 REST POST /api/v1/fetch 与 MCP execute_sql_query / fetch_next_batch 当前公开的结果契约。推荐的 PostgreSQL/MySQL 任务配置在分页和流式批次中使用同一行编码逻辑。

## 响应与续取

Fetch 响应包含 columns、entries、totalCount、可选的 nextUri 和实际执行模式。entries 中每一行都按 columns 的顺序排列。REST 会把该对象放入标准响应封装；MCP 工具文本中返回相同的 JSON 对象。

存在 nextUri 时，客户端应请求该续取地址，并使用每次成功批次返回的最新会话令牌。成功响应省略 nextUri，是 API 当前提供的完成信号：按所选路径观察到的计数/游标状态，当前没有后续批次。如果数据源行在跨页期间变化，这并不承诺跨页快照。批次长度不能代表完成：较短的一页仍可能有后续页，满页也可能是最后一页。type 1、type 2、自动模式以及回退到分页时，都应按 nextUri 继续。

totalCount 由单独的计数操作计算。对 PostgreSQL/MySQL 配置，它描述该计数操作看到的 SQL 结果行数，并保留请求绑定参数和 SQL 自身的 LIMIT 范围。它不是跨页快照计数；如果查询启动或取页期间数据源发生变化，计数可能和实际遍历行数不一致。若无法安全计算计数，请求可能失败，而不是返回编造的数量。例如，部分数据库无法对输出列名重复的 DISTINCT 查询计算派生表计数；可为各列使用不同的别名后重试。

## 执行模式

- **分页**：每次续取都会用 LIMIT 和 OFFSET 重新执行 SQL。每次请求都有限制，且请求之间会释放数据库连接；但不同页可能观察到不同的数据源状态。
- **流式**：请求之间保留数据源游标，直到游标结束、被取消、过期或被查询预算停止。游标存活期间会占用数据源资源。快照/隔离语义取决于数据源驱动和事务行为；Data Fabric 不承诺跨数据源的一致快照。
- **自动模式**：executionMode 表示实际使用的路径。REST 可用 type: 1 选择分页，或用 type: 2 请求流式；MCP 可传 execution_mode: "pagination" 或 "streaming"。默认优先流式。显式服务端执行配置可以覆盖请求，因此客户端应检查 executionMode。两种路径的续取规则相同。

超时、会话过期、取消、数据源失败或查询预算错误，都表示已有前置页时整个逻辑结果尚未完成。不要把这些页描述为完整结果。续取错误时应遵循错误和令牌状态；如果会话无法继续，应重新执行逻辑查询，并丢弃旧页或明确标注旧页为部分结果。

## 排序和跨页数据变化

对于固定的数据源状态，如果顺序重要，应使用带唯一且稳定的排序键的 ORDER BY。没有 ORDER BY 时，SQL 不保证结果顺序；排序键不唯一时，相同键的行仍可能跨页移动。

分页不是快照。在两次取页之间插入、删除，或更新被选择、过滤、排序的值，都可能移动 OFFSET，导致相对于某个想象中的时点结果出现重复行或漏行。唯一排序只能让固定数据集的顺序可重复，不能阻止数据变化导致的偏移。当前公开配置不承诺分页跨页快照。可重复的首次采用任务应使用只读且无并发写入的参考数据；要求跨页快照的生产任务需要单独支持一致性机制。

流式会保留游标而不是重新执行 SQL，但其快照/隔离保证取决于数据源驱动和事务语义。totalCount 与游标查询分开执行，因此不能证明游标的快照大小。

## 值编码和当前证据边界

共享 Fetch 编码器会把 SQL NULL 保留为 JSON null，把文本字节保留为文本，把二进制字节编码为标准 Base64，把 int64 保留为 JSON 整数，并保留 DECIMAL 文本。公共参考数据已核对整数、DECIMAL 的精确值，以及 SQL NULL 和字符串 "NULL" 的区别。A28 的数据变化观测限定于固定版本的参考 MySQL/PostgreSQL 镜像，不构成跨驱动快照保证。时间类型、时区/小数精度、浮点边界、二进制往返，以及各数据源的计数成本，在获得候选版本匹配的契约记录前仍不能描述为跨源统一保证。

当前公共验收矩阵通过实际 REST/MCP 响应记录唯一排序、非唯一排序和无排序下的跨页插入、删除、更新，并区分重新执行的分页与持有游标的流式路径。候选产物会记录合成行 ID。#455 保持开放，直到选定候选通过这些结果检查，并确保静默截断行为有门禁。
