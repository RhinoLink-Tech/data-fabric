# Deployment Footprint Baseline\n\n**Measured:** 2026-11-01\n**Source commit:** a03e1988fafd28bce72fae5f7e043b06c30f1c4d\n**Purpose:** Establish a reproducible local baseline for the Data Fabric release artifact and runtime process. This is not a production guarantee or a comparison with another product.\n\n## Environment\n\n| Item | Measured environment |\n| --- | --- |\n| Host CPU | Intel Core Ultra 9 275HX |\n| Logical CPUs visible to WSL | 24 |\n| Host memory visible to WSL | 16,466,497,536 bytes (about 15.34 GiB) |\n| OS | Ubuntu on WSL2, Linux 6.18.33.2-microsoft-standard-WSL2, x86_64 |\n| Docker Engine | 29.8.0 |\n| Go builder | golang:1.26.1, as pinned in the Dockerfile |\n| Synthetic source and metadata DB | MySQL 8.4.13, resolved image digest mysql@sha256:a0225d1ea6631c8bc2385dc4c2faba17bbf1834ecf369e1659a9a382bd8d5dd7 |\n| Data Fabric mode | release |\n| Application container memory limit | None |\n\nThe disposable MySQL instance stores Data Fabric metadata in one database and the synthetic source table in a separate database. Its CPU and memory are not included in Data Fabric RSS measurements.\n\n## Results\n\n| Measurement | Result |\n| --- | ---: |\n| Release server binary | 172,161,122 bytes (164.2 MiB) |\n| Final Docker image, uncompressed | 326,102,374 bytes (311.0 MiB) |\n| First start to healthy readiness, including initial metadata migrations | 0.600 s |\n| Restart to healthy readiness, 5 samples, median (range) | 0.493 s (0.482–0.521 s) |\n| Idle process RSS after 5 seconds, 5 samples, median (range) | 82.65 MiB (82.51–83.52 MiB) |\n| Small one-row query process high-water RSS, 3 samples, median (range) | 84.43 MiB (83.88–84.76 MiB) |\n| Bounded stream process high-water RSS, 3 samples, median (range) | 95.64 MiB (95.35–97.78 MiB) |\n\nThe bounded stream returned 50,000 rows with a 256-byte payload in batches of 1,000 rows (50 HTTP requests). The RSS values are Data Fabric container PID 1 measurements from /proc/1/status. VmHWM is the process high-water mark since process start, not an isolated per-query allocation measurement. The DB containers and load-generating client are outside the Data Fabric container. No concurrent client load was applied.\n\nThe image size is Docker's uncompressed local image size, not the compressed registry transfer size. The test uses one machine, one MySQL version, one source shape, one request at a time, and no container memory cap. Do not extrapolate these values to other hardware, providers, concurrency levels, or production deployments.\n\n## Packaging Follow-up\n\nA local Linux/amd64 build of the same source using the Go linker flags -s -w measured 125,284,514 bytes (119.5 MiB), compared with 172,161,122 bytes for the release binary. That compile-only variant is 46,876,608 bytes (about 27.2%) smaller. It has not been adopted or validated as a release image; [issue #293](https://github.com/RhinoLink-Tech/data-fabric/issues/293) tracks applying and verifying this packaging change. Runtime measurements above use the existing unstripped release image.\n\n## Reproduce\n\nRequirements: Docker, Python 3, and network access to pull the pinned MySQL image if it is not cached. Go is built inside the pinned Dockerfile builder image.\n\nFrom a clean checkout, run:\n\n~~~bash\npython3 scripts/performance/deployment_footprint_benchmark.py\n~~~\n\nThe runner builds the production Dockerfile, extracts the release binary to measure its size, then creates uniquely named temporary Docker network and MySQL/Data Fabric containers. It generates temporary database, JWT, and credential-vault keys; it never writes credentials to the report or sample CSV. The containers, network, generated local binary, and built Data Fabric image are removed on exit. The pinned MySQL image remains in the local Docker cache.\n\nDefaults are 50,000 source rows, 256-byte payloads, 1,000-row stream batches, five startup samples, three query samples per workload, and a five-second idle settling period. To change the source row count or raw sample destination, set DATA_FABRIC_FOOTPRINT_ROWS or DATA_FABRIC_FOOTPRINT_RAW_OUTPUT before running. The runner writes a raw CSV and a JSON environment record under docs/performance/results/.\n\nThe raw files for this run are [CSV samples](results/deployment_footprint_2026-11-01.csv) and [environment metadata](results/deployment_footprint_2026-11-01.json).\n
