# 单机元数据：SQLite 候选评估

[English](single-node-metadata-evaluation.md) · 跟踪 [#444](https://github.com/RhinoLink-Tech/data-fabric/issues/444)

状态：**已有仅供源码构建的实验原型**，尚非正式支持的后端。参见[原型说明](sqlite-metadata-prototype-zh.md)。你的需求是简单部署、少占资源，并避免在本机下载大型镜像。现有参考部署需要独立 MySQL 保存管理元数据，REST 和 MCP 共用它；业务数据库和可选 Trino 又是独立组件。[#448](https://github.com/RhinoLink-Tech/data-fabric/issues/448) 的网关镜像测量并不包含这些组件。

2026-11-19 本机已有 `mysql:8.4.13` 的 Docker `Size` 为 1,102,620,445 字节，镜像 ID 为 `sha256:a81d043930e51745522bd5c430961cf8286f0a23f0a9a2a6e0108f7ea71b0902`；这是本机 Docker 的单次值，不等于网络下载量、内存或其他机器的结果。本次没有拉取镜像。这个事实说明部署负担值得评估，但不能据此推断 SQLite 最终能节省多少。

## 已确认的限制

- 当前[元数据初始化](../../internal/config/database.go)使用 MySQL 驱动；配置没有可选择的生产 SQLite 后端。测试代码或个别存储组件能使用 SQLite，不等于产品已支持它。
- 发布 [Dockerfile](../../Dockerfile) 关闭 CGO。对当前依赖的 SQLite 驱动做离线合成测试，Go 1.26.1 在 `CGO_ENABLED=0` 下连接内存数据库会返回驱动桩错误。直接启用测试依赖不能得到可工作的发布版本。
- [数据源更新](../../internal/repository/datasource_locked_update.go)、[浏览器状态](../../internal/security/browserauth/store.go)、[授权记录](../../internal/security/onboarding/grant_store.go)和[策略发布](../../internal/security/table_policy_manager.go)使用事务及更新锁；当前 SQLite GORM 驱动会省略行级 `FOR UPDATE`。现有 SQLite 单元测试不能证明跨进程的授权、撤销和策略发布语义不变。每个进程只开一个连接，也不能证明跨进程安全。

## 建议路线

| 方案 | 价值 | 代价与前置条件 |
| --- | --- | --- |
| 保留 MySQL 元数据 | 继续使用现有参考部署，不迁移数据。 | 仍需单独服务、镜像与配置，可复用已有缓存。 |
| 可选单机 SQLite | 有机会去掉单机部署的元数据服务，数据保存在持久文件中。 | 选择并验证 CGO 构建或纯 Go 驱动，核对许可、跨平台构建及体积；针对实际 REST/MCP 进程设计事务、锁等待和错误处理。 |
| [合并 REST/MCP 进程 #443](https://github.com/RhinoLink-Tech/data-fabric/issues/443) | 可能减少进程和配置步骤。 | 需单独测量；它本身不会去掉 MySQL，也不能替代 SQLite 正确性验证。 |

继续完善**单机可选原型**，发布前完成驱动和事务设计评审；MySQL 继续作为默认方案，旧数据不自动迁移。嵌入式文件不等于多机共享、高可用或自动升级。文件必须位于支持的本机持久文件系统，不能默默落到容器临时层或网络文件系统。

## 验收路径

1. 固定驱动，验证与发布版本相同的 Linux 构建能够打开文件，测量新二进制和镜像；沿用凭证加密及密钥要求。
2. 明确权限、迁移、日志模式、持久性、锁等待和关闭行为；只读目录、磁盘满、文件损坏、缺密钥及锁冲突均须给出清楚且不泄密的错误。设计一致性备份与恢复，不能假设运行中只复制数据库文件就安全。
3. 在单机的实际进程拓扑中，用合成数据完成创建数据源、重启、REST/MCP 读取和查询、授权撤销、审计与备份恢复；确认数据源 ID、加密凭证、策略版本和审计记录持久化。不使用 Atlas 数据。
4. 用两个进程验证同时修改、撤销授权和竞争发布策略，包括强制退出与中断事务；保证可解释的先后顺序，或安全失败。这里是基本正确性验证，不是高并发性能测试。
5. 用相同任务比较 MySQL 和 SQLite 方案的整套镜像、启动时间、空闲内存、持久存储及备份维护成本；记录镜像、代码版本、配置和机器，先测量再宣传。

实际发布和 WorkBuddy 对外宣传仍需完成 #444 的全部契约及真实客户端验收。本评估不会修改现有元数据服务、发布镜像或迁移数据。
