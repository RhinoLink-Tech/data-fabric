# 独立首次使用演练协议

状态：仅完成准备，尚无独立操作者的实际结果。

本协议服务于 Issue #446：使用带版本的基线 artifact 和候选 artifact，对比文档中的首次使用路径。本协议不能证明持续团队采用（#458）、真实模型任务质量（#456）、生产就绪或客户价值。

## 开始前的门槛

仅在以下条件都满足后开始演练：

- 基线和候选的发布 tag、源码 SHA、镜像 digest、平台及对应文档均已锁定。使用已发布 artifact，不得以本地构建或源码 checkout 替代。
- 两个 artifact 及依赖镜像均须可匿名获取。v2.1.0-preview.1 候选现已公开，digest 为 `sha256:7d47073fe806879968ed3c66f9d3b2b7b7a2020f419738c2cbb1b89d58f1ebbf`（[发布页](https://github.com/RhinoLink-Tech/data-fabric/releases/tag/v2.1.0-preview.1)）；匿名拉取和 clean-runner 验收已通过。安排操作者前，还需确认基线 artifact 和依赖镜像也满足该门槛。
- 至少两名未参与引导路径实现、且不熟悉仓库内部细节的操作者参与。他们获得已发布说明和同一份任务说明，不由维护者带着操作。
- 隔离环境使用合成数据或经明确批准用于本次演练的数据。

任何门槛不满足时，记录阻塞原因并停止。计划中或未完成的演练不能记为通过。

## 控制镜像下载和环境

计时前记录主机操作系统和架构、Docker Engine 与 Compose 版本、身份提供方设置、数据源版本、策略，以及两个 artifact 所需的精确镜像引用和 digest。

检查本地是否已缓存对应 digest。仅在确认传输大小和流量预算后，才可在计时前一次性准备缺失镜像。不要解析可变 tag，也不要触发计划外下载。如果缺失镜像会导致较大传输，暂停并安排获准的预缓存或离线传输。单独记录传输字节数和缓存状态，不计入操作者耗时。

基线和候选使用同一台主机或等效主机限制、身份提供方、合成数据行、tenant 映射和策略。每个 artifact 使用新的 Compose project 和测试卷启动，再按文档清理并重置。操作者、客户端和应用之间不得共享 bearer token。

平衡学习顺序：操作者 A 先跑基线再跑候选；操作者 B 先跑候选再跑基线。记录每次解释和维护者介入。

## 执行同一任务

每名操作者、每个 artifact 都执行以下步骤：

1. 操作者拿到 artifact 身份、任务说明和文档链接时开始计时。按已发布的部署和首次使用指南操作，不 checkout 仓库。
2. 在预期 owner 和 tenant 下注册合成只读数据源，完成首次授权查询并对照 fixture 预期。报告中不要粘贴原始数据行。
3. 使用未授权 tenant 的 principal 重复发现或查询。数据源和数据行必须不可见。若配置受限表或列，确认其隐藏或被拒绝。
4. 使用第二个应用及其独立 OIDC principal，并映射到获准的 tenant。第二应用应复用已登记的数据源和策略，不获得数据源凭据，并完成同一项授权任务。
5. 执行一种文档定义的安全失败场景，例如 MCP token 缺失或过期。记录预期下一步及客户端可见的 correlation ID。不得使用管理员身份绕过访问失败。
6. 完成授权任务、拒绝场景和第二应用检查后停止计时。分别记录操作者主动用时、总耗时、失败、重试和维护者介入。
7. 只清理本轮演练的 Compose project 和测试卷。详细日志存放于获准的存储；报告只保留脱敏引用。

若出现意外放行、非预期写入、凭据泄露或超出授权范围的数据暴露，立即停止。只保留脱敏事件引用，并遵循环境负责人的响应流程。
