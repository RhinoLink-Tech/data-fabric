# Install the v2.1.0-preview.3 image

[中文](v2.1.0-preview.3-install-zh.md) · [Candidate scope and risks](v2.1.0-preview.3-candidate.md) · [Release downloads and immutable image digest](https://github.com/RhinoLink-Tech/data-fabric/releases/tag/v2.1.0-preview.3)

This guide applies only after `v2.1.0-preview.3` has a published GitHub Release and an immutable image digest. It starts one self-hosted `linux/amd64` evaluation profile with MySQL 8.4 metadata and synthetic sample data. It is not a production, high-availability, performance-SLA, automatic-failover, or arbitrary-client OAuth guide.

You need Docker Engine 24+, Docker Compose 2.24+, Python 3, OpenSSL, `curl`, `tar`, and `sha256sum`. The release image itself does not need a Go compiler or host Python packages. Remote MCP additionally needs a trusted HTTPS endpoint, an OIDC issuer, a configured audience, and a token with the documented query scope. Use a new Compose project and synthetic or explicitly approved data.

## 1. Download and verify the release files

Run this in a new empty directory after checking the archive checksum in the release record:

```bash
VERSION=v2.1.0-preview.3
ARCHIVE="data-fabric-${VERSION}-source.tar.gz"
BASE="https://github.com/RhinoLink-Tech/data-fabric/releases/download/${VERSION}"
curl -fL -o "$ARCHIVE" "$BASE/$ARCHIVE"
curl -fL -o "$ARCHIVE.sha256" "$BASE/$ARCHIVE.sha256"
sha256sum -c "$ARCHIVE.sha256"
tar -xzf "$ARCHIVE"
cd "data-fabric-${VERSION}/deploy/mcp"
```

Stop if checksum validation fails. It verifies the downloaded source archive, not the image. Do not substitute an unpublished image or a digest copied from another version.

## 2. Initialize and configure

Choose an unused Compose project name and retain it in later shells:

```bash
export COMPOSE_PROJECT_NAME=data-fabric-preview3
python3 ../../scripts/mcp/onboard.py init --directory "$PWD"
```

Keep `.env` mode `0600`. Set `MCP_OIDC_ISSUER` and `MCP_OIDC_AUDIENCE` for your own identity provider and configure the required scope. Copy the **complete tag-and-digest reference** from the matching GitHub Release into the one uncommented `DATA_FABRIC_IMAGE` entry in `.env`.

```text
ghcr.io/rhinolink-tech/data-fabric:v2.1.0-preview.3@sha256:<release-digest>
```

That line is only the required shape; `<release-digest>` is not usable. The generated certificate is for local evaluation. Use a trusted certificate before remote use, and protect `.env`, the TLS private key, and the credential keyring. Losing or replacing the keyring can make saved data-source credentials unreadable.

## 3. Start and diagnose the profile

```bash
docker compose -f docker-compose.yml -f docker-compose.release.yml pull
docker compose -f docker-compose.yml -f docker-compose.release.yml up -d
docker compose -f docker-compose.yml -f docker-compose.release.yml ps
python3 ../../scripts/mcp/onboard.py doctor --directory "$PWD"
```

Wait for services to become healthy. An unauthenticated MCP probe returning `401` is expected. An authorized remote MCP task still needs a working identity provider and token. Do not put passwords or bearer tokens in a Skill prompt, source URL, or shell history.

## 4. Add the synthetic source and complete a first query

Follow the [management and MCP identity instructions](../mcp-deployment.md#5-prepare-management-and-mcp-access-tokens), [sample registration](../mcp-deployment.md#6-register-the-sample-source), and [first query](../mcp-deployment.md#7-connect-a-client-and-run-the-first-query). The sample records are synthetic.

Use the [Agent Skill guide](../agent-skill.md) to configure a supported client. Data Fabric offers read-only discovery and querying; it is not an ELT data-movement service. SQL conversion can translate between advertised dialects without executing a query, but conversion does not make arbitrary vendor SQL portable or authorize a data source.

The primary evaluated source path is the documented MySQL profile. Consult the [support catalog](../data-source-support.md) before configuring another type. Browser onboarding candidates, public WorkBuddy self-service, arbitrary-client automatic OAuth, and every registered source/version are not implied by this guide.

## Recovery and upgrade limits

Use a fresh isolated project and volumes for this Preview. An in-place upgrade from v2.0.0 or earlier Preview builds is not an established promise. Before using data that matters, independently exercise backup and restore with retained key material; source databases and live query cursors are not included in a profile backup.

Keep the exact release archive, `.env`, TLS key, credential keyring, image digest, and source revision together in your change record. The candidate's known limitations, including the current keyring-recovery boundary and public OAuth/WorkBuddy exclusions, are listed in the [candidate record](v2.1.0-preview.3-candidate.md).
