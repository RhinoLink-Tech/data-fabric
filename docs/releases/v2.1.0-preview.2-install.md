# Install the v2.1.0-preview.2 image

[中文](v2.1.0-preview.2-install-zh.md) · [Release downloads and exact image digest](https://github.com/RhinoLink-Tech/data-fabric/releases/tag/v2.1.0-preview.2) · [Preview scope and risks](v2.1.0-preview.2-candidate.md)

This guide is for the published `v2.1.0-preview.2` release once its release page and immutable image digest are available. It runs a single-host `linux/amd64` evaluation profile with synthetic MySQL data. It is not a production, high-availability or SLA guarantee.

You need Docker Engine 24+, Docker Compose 2.24+, Python 3, OpenSSL, `curl`, `tar`, and `sha256sum`. Remote MCP also requires an HTTPS OIDC issuer, a correctly configured audience and an access token with the required `data-fabric.query` scope. The image path does not require a Go compiler or host Python packages. Use a new Compose project and synthetic or explicitly approved data.

## 1. Download and verify the release files

Run in a new empty directory, after checking the archive SHA-256 in the release record:

```bash
VERSION=v2.1.0-preview.2
ARCHIVE="data-fabric-${VERSION}-source.tar.gz"
BASE="https://github.com/RhinoLink-Tech/data-fabric/releases/download/${VERSION}"
curl -fL -o "$ARCHIVE" "$BASE/$ARCHIVE"
curl -fL -o "$ARCHIVE.sha256" "$BASE/$ARCHIVE.sha256"
sha256sum -c "$ARCHIVE.sha256"
tar -xzf "$ARCHIVE"
cd "data-fabric-${VERSION}/deploy/mcp"
```

Stop if validation fails. The checksum checks the downloaded source archive, not the image; compare the value in the checksum file with the release record. Do not substitute an unpublished or unverified artifact.

## 2. Initialize and configure

Choose a Compose project name unused by any other installation and retain it in later shells:

```bash
export COMPOSE_PROJECT_NAME=data-fabric-preview2
python3 ../../scripts/mcp/onboard.py init --directory "$PWD"
```

Keep `.env` mode `0600`. Set `MCP_OIDC_ISSUER` and `MCP_OIDC_AUDIENCE` for your identity provider, and configure the required scopes. Copy the **complete tag@sha256 reference** from the matching GitHub Release into the one uncommented `DATA_FABRIC_IMAGE` entry in `.env`. An illustrative shape is `ghcr.io/rhinolink-tech/data-fabric:v2.1.0-preview.2@sha256:<digest>`; the placeholder is not a usable image.

The generated localhost certificate is for local evaluation. Use an appropriate trusted certificate for remote access. Preserve the `.env`, TLS private key and credential keyring securely: changing or losing the keyring can make saved source credentials unreadable. See the [deployment guide](../mcp-deployment.md#2-tls-certificate-and-private-key-access).

## 3. Start and check

```bash
docker compose -f docker-compose.yml -f docker-compose.release.yml pull
docker compose -f docker-compose.yml -f docker-compose.release.yml up -d
docker compose -f docker-compose.yml -f docker-compose.release.yml ps
python3 ../../scripts/mcp/onboard.py doctor --directory "$PWD"
```

Allow the services to become healthy. An unauthenticated MCP probe returning `401` is expected. An authorized remote MCP query still needs a working identity provider and access token.

## 4. Register a sample and query it

Follow the [management and MCP identity instructions](../mcp-deployment.md#5-prepare-management-and-mcp-access-tokens), [sample registration](../mcp-deployment.md#6-register-the-sample-source), and [first query](../mcp-deployment.md#7-connect-a-client-and-run-the-first-query). Keep the management identity and OIDC subject/tenant aligned. The sample records are synthetic. For client setup, see the [Agent Skill guide](../agent-skill.md) and check its stated client and feature limitations.

## Upgrade and recovery limits

Use a fresh isolated project and new volumes; an in-place upgrade from v2.0.0 or preview.1 has not been established. The archive-based recovery allowlist currently recognizes preview.1, not this archive. Backup also has the effective-keyring limitation in [#522](https://github.com/RhinoLink-Tech/data-fabric/issues/522). Do not rely on an untested backup or restore for valuable data; verify the procedure and retained key material independently before migration. Business-source databases and live cursors are not included in the profile backup.

Public WorkBuddy self-service account provisioning and arbitrary MCP-client automatic OAuth onboarding are not included in this Preview's supported profile; see [#603](https://github.com/RhinoLink-Tech/data-fabric/issues/603) and [#608](https://github.com/RhinoLink-Tech/data-fabric/issues/608).
