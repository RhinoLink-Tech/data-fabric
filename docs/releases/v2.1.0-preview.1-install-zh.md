# 安装 v2.1.0-preview.1 发布镜像

[English](v2.1.0-preview.1-install.md) · [版本说明和支持范围](https://github.com/RhinoLink-Tech/data-fabric/releases/tag/v2.1.0-preview.1)

本指南在一台 `linux/amd64` 主机上安装公开 Preview 镜像，包含合成的 MySQL 示例数据。这是评估配置，不承诺生产可用性、高可用、自动故障切换或 SLA。镜像对应源码 revision `570c2975fedbc886a37003a8b64b68caa699678c`，发布后 `master` 上的修复不包含在该镜像中。

需要 Docker Engine 24+、Docker Compose 2.24+、Python 3 标准库、OpenSSL、`curl`、`tar` 和 `sha256sum`。远程 MCP 还需要 HTTPS OIDC 身份提供方，能签发符合配置的 audience 且包含 `data-fabric.query` scope 的 JWT access token。不需要 Go 编译器或宿主机 Python 第三方包。请使用全新的隔离 Compose 项目和合成数据，或明确获准的数据。

## 1. 下载并校验发布文件

在全新的空目录执行：

```bash
curl -fL -o data-fabric-v2.1.0-preview.1-source.tar.gz \
  https://github.com/RhinoLink-Tech/data-fabric/releases/download/v2.1.0-preview.1/data-fabric-v2.1.0-preview.1-source.tar.gz
printf '%s  %s\n' \
  75714a13772b6a23940eece7a315bcc8d1c9715567e8d2ffb0021a4a9692c9dc \
  data-fabric-v2.1.0-preview.1-source.tar.gz | sha256sum -c - && \
  tar -xzf data-fabric-v2.1.0-preview.1-source.tar.gz && \
  cd data-fabric-v2.1.0-preview.1/deploy/mcp
```

校验失败时停止。压缩包提供 Compose 文件和脚本，无需编译源码。**归档备份：**原压缩包包含旧版恢复工具。如需不依赖 Git 的可验证备份，请使用新版工具并按[压缩包备份恢复说明](../operations/mcp-profile-backup-recovery-zh.md)操作；保留原始下载压缩包供校验。

## 2. 初始化并配置

选择未被其他安装使用的 Compose 项目名，后续打开新 shell 时也使用同一名称。初始化会生成 `.env` 和本地 TLS 文件，不替换现有非空密钥：

```bash
export COMPOSE_PROJECT_NAME=data-fabric-preview1
python3 ../../scripts/mcp/onboard.py init
```

编辑 `.env`（保持权限 `0600`）：将 `MCP_OIDC_ISSUER` 设为身份提供方的 HTTPS issuer，将 `MCP_OIDC_AUDIENCE` 设为已注册的 audience。`MCP_OIDC_REQUIRED_SCOPES` 必须包含 `data-fabric.query`。再添加下面这一条未注释的精确镜像引用：

```dotenv
DATA_FABRIC_IMAGE=ghcr.io/rhinolink-tech/data-fabric:v2.1.0-preview.1@sha256:7d47073fe806879968ed3c66f9d3b2b7b7a2020f419738c2cbb1b89d58f1ebbf
```

生成的 localhost 证书用于本地评估。远程访问应使用适当的受信任证书，并妥善保存私钥、`.env` 和凭证密钥环；替换密钥环可能导致已保存的数据源凭证无法解密。详见 [TLS 与身份配置](../mcp-deployment-zh.md#1-初始化本地配置)。

## 3. 启动并检查

```bash
docker compose -f docker-compose.yml -f docker-compose.release.yml pull
docker compose -f docker-compose.yml -f docker-compose.release.yml up -d
docker compose -f docker-compose.yml -f docker-compose.release.yml ps
python3 ../../scripts/mcp/onboard.py doctor
```

等待四个服务均变为健康。doctor 检查本地配置、服务状态、API 健康、MCP TLS/认证及解析器；未认证的 MCP 探测返回 `401` 属于预期。完成授权查询仍需要可用的 OIDC 身份提供方及 access token。

## 4. 登记示例并执行查询

先从身份提供方获取 JWT access token。管理身份的 `DF_USER_ID` 应与 token 中稳定的 `sub` 一致，tenant 也要与 token 的 tenant claim 对齐。以下命令在 `deploy/mcp/` 执行，将合成 MySQL 示例注册为只读数据源：

```bash
export DF_USER_ID='<OIDC access token 中稳定的 sub>'
export DF_TENANT_ID='quickstart'
export DF_MANAGEMENT_TOKEN="$(python3 ../../scripts/mcp/onboard.py token \
  --user "$DF_USER_ID" --tenant "$DF_TENANT_ID")"
SAMPLE_READER_PASSWORD=$(grep -E '^SAMPLE_READER_PASSWORD=' .env | cut -d= -f2-)
curl -fsS http://127.0.0.1:8080/api/v1/datasources \
  -H "Authorization: Bearer $DF_MANAGEMENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"sample-mysql\",\"type\":\"mysql\",\"config\":{\"host\":\"sample-source\",\"port\":3306,\"database\":\"sample\",\"username\":\"sample_reader\",\"password\":\"$SAMPLE_READER_PASSWORD\"}}"
```

记录返回的数据源 `id`。管理 token 默认只有效 15 分钟，不能用于远程 MCP；MCP 客户端需要身份提供方签发的 access token。不要公开 token、`.env` 或密码。配置 MCP 客户端后，依次调用 `list_data_sources`、`list_tables`、`describe_table`，再用 `execute_sql_query` 执行 `SELECT customer, amount FROM orders ORDER BY amount DESC`。示例数据均为合成数据。更完整的[身份和 token 配置](../mcp-deployment-zh.md#3-生成短时管理-token)及 [Agent Skill 指南](../agent-skill-zh.md)包含客户端连接说明；使用时确认该 Preview 镜像已包含相关功能。
