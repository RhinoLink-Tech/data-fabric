# Install the v2.1.0-preview.1 image

[中文](v2.1.0-preview.1-install-zh.md) · [Release and support boundaries](https://github.com/RhinoLink-Tech/data-fabric/releases/tag/v2.1.0-preview.1)

This version-specific guide installs the public `linux/amd64` Preview image on one host with a synthetic MySQL sample. It is an evaluation profile, not a production, HA, failover or SLA promise. The image is built from source revision `570c2975fedbc886a37003a8b64b68caa699678c`. Later changes on `master` are not included in this published image.

You need Docker Engine 24+, Docker Compose 2.24+, Python 3 with its standard library, OpenSSL, `curl`, `tar`, and `sha256sum`. Remote MCP also needs an HTTPS OIDC provider that issues JWT access tokens with the configured audience and `data-fabric.query` scope. No Go compiler or host Python packages are needed. Use a new, isolated Compose project and synthetic or explicitly approved data.

## 1. Get and verify the release files

Run this in a new, empty directory:

```bash
curl -fL -o data-fabric-v2.1.0-preview.1-source.tar.gz \
  https://github.com/RhinoLink-Tech/data-fabric/releases/download/v2.1.0-preview.1/data-fabric-v2.1.0-preview.1-source.tar.gz
printf '%s  %s\n' \
  75714a13772b6a23940eece7a315bcc8d1c9715567e8d2ffb0021a4a9692c9dc \
  data-fabric-v2.1.0-preview.1-source.tar.gz | sha256sum -c - && \
  tar -xzf data-fabric-v2.1.0-preview.1-source.tar.gz && \
  cd data-fabric-v2.1.0-preview.1/deploy/mcp
```

Stop if the checksum does not match. The archive contains the Compose files and scripts; it does not require a source build. Alternatively, download the [checksum file](https://github.com/RhinoLink-Tech/data-fabric/releases/download/v2.1.0-preview.1/data-fabric-v2.1.0-preview.1-source.tar.gz.sha256) next to the archive and run `sha256sum -c data-fabric-v2.1.0-preview.1-source.tar.gz.sha256` in that directory. Both commands validate the source archive, not the image. **Archive backup:** the original archive contains an older recovery helper. For a verified backup without Git, use the updated helper and the [archive recovery instructions](../operations/mcp-profile-backup-recovery.md#alternative-the-published-v210-preview1-source-archive); keep the original downloaded archive for verification.

## 2. Initialize and configure

Choose a Compose project name that is not used by another installation and keep using it in later shells. Initialization creates `.env` and local TLS material without replacing existing non-empty secrets:

```bash
export COMPOSE_PROJECT_NAME=data-fabric-preview1
python3 ../../scripts/mcp/onboard.py init
```

Edit `.env` (keep permissions `0600`): set `MCP_OIDC_ISSUER` to your provider's HTTPS issuer and `MCP_OIDC_AUDIENCE` to its registered audience. Set `MCP_OIDC_REQUIRED_SCOPES` to include `data-fabric.query`. Add this exact image reference as one uncommented line:

```dotenv
DATA_FABRIC_IMAGE=ghcr.io/rhinolink-tech/data-fabric:v2.1.0-preview.1@sha256:7d47073fe806879968ed3c66f9d3b2b7b7a2020f419738c2cbb1b89d58f1ebbf
```

The generated localhost certificate is for local evaluation. Use an appropriate trusted certificate for remote access, and retain the private key, `.env`, and credential keyring securely; replacing the keyring can make stored source credentials unreadable. See [TLS and token configuration](../mcp-deployment.md#2-tls-certificate-and-private-key-access).

## 3. Start and check

```bash
docker compose -f docker-compose.yml -f docker-compose.release.yml pull
docker compose -f docker-compose.yml -f docker-compose.release.yml up -d
docker compose -f docker-compose.yml -f docker-compose.release.yml ps
python3 ../../scripts/mcp/onboard.py doctor
```

Allow time for all four services to become healthy. The doctor checks local configuration, service health, API health, MCP TLS/auth, and the parser. A `401` from the unauthenticated MCP probe is expected. A working OIDC provider and token are still needed for an authorized MCP query.

## 4. Register the sample and run a query

Continue with [management and MCP tokens](../mcp-deployment.md#5-prepare-management-and-mcp-access-tokens), [sample registration](../mcp-deployment.md#6-register-the-sample-source), and [the first query](../mcp-deployment.md#7-connect-a-client-and-run-the-first-query). Keep the management principal and OIDC subject/tenant aligned as described there. The sample data is synthetic. Use the [Agent Skill guide](../agent-skill.md) for client-specific setup, while checking whether its documented features are available in this Preview image.

The [source-build quickstart](../mcp-deployment.md#quickstart) is for developers. The exact published tag and digest were accepted on a clean runner using tagged deployment files; see the [release verification record](https://github.com/RhinoLink-Tech/data-fabric/releases/tag/v2.1.0-preview.1). External adoption and production readiness remain unverified.
