## 支持的评估配置

在一台 `linux/amd64` 主机上自部署文档化 Compose 配置，使用 MySQL 8.4 元数据和合成 MySQL 样例数据，通过 REST 管理，并以正确配置的外部 OIDC 签发方与可信 TLS 提供远程 MCP。发布镜像必须包含固定版本的 SQL 转换运行时和许可证材料。其他数据源仅可按照[支持目录](../data-source-support.md)中已有的操作与验证证据选择。

这是一份评估发布，不承诺生产就绪、高可用、自动故障切换、支持窗口、性能 SLA、通用 SQL、ELT 或跨连接器兼容。已测试的单机配置不能证明集群级查询配额或游标故障切换。部署时间与资源使用取决于主机和工作负载。

公开 WorkBuddy 服务、自助租户开通、任意客户端的自动 OAuth 和市场生命周期均不在支持范围内。浏览器数据源接入和更新均为默认关闭的候选功能，仍需各自的身份、网络、驱动和客户端验收；发布镜像本身不能证明它们能在 WorkBuddy 中使用。

## 候选版本中的用户可见变化

- **只读 Agent 数据访问：** MCP 数据源发现和授权表结构检查支持分页，并相对于当前调用者返回结果。元数据可用时，表结果会带有经授权的 schema 身份，便于区分同名表。
- **有边界的查询：** MCP 首页默认 100 行，明确指定时最多 10,000 行，续页保留有效上限。无总数模式仅适用于 MySQL、MariaDB、PostgreSQL 与 Trino；未知总数为 `null`，默认仍是精确总数。
- **SQL 转换：** 仓库 Skill 以及 REST/MCP 转换能力可发现已公布的方言、规范化已文档化别名、校验同方言输入，并在不执行 SQL 的情况下转换。它不保证任意厂商 SQL 的语义可移植。
- **更安全的数据源操作：** 创建和更新会做连接器专属校验；已授权编辑者可以测试服务端保存的凭据，但不会收到凭据。浏览器接入流程失效或不可用时，会提示从 MCP 客户端重新发起，而不是在浏览器存储密码。
- **明确的支持边界：** GBase 8s/8t 配置不再静默使用未经验证的适配器，缺少原生驱动时达梦会显示为不可用。这是安全披露，不代表新增支持。

## 已记录的发布风险决定

打标签前必须重新检查 issue 状态和安全公告。若新发现的问题会让所选配置不安全或无法完成所宣传的首次任务，则属于发布阻塞；下列延期不代表问题已经修复。

## 制品与验收门槛

1. 合入本文后冻结精确主线提交，并要求该 SHA 的 push CI 成功，包括合同选择、单元/构建、PostgreSQL/MySQL/MariaDB 参考合同和公开 REST/MCP 验收。
2. 对冻结 SHA 运行隔离的加密备份与全新卷恢复工作流。它只是源码候选证据；已发布 preview.2 的归档/镜像演练需独立保留。
3. 复核支持矩阵、发布说明、已知限制和以上风险决定。只有在确定版本/标签时，才把已审定的 Unreleased 条目移入带日期的版本段落。
4. 确认版本标签和源码 SHA 镜像标签均未使用，再在精确审定的主线提交上创建带注释的 `v2.1.0-preview.3` 标签。标签工作流必须发布带 SBOM 和 provenance 的 `linux/amd64` 镜像。
5. 记录公开且不可变的 `tag@sha256`、源码版本和平台。对该精确摘要运行已发布镜像验收；文档化的无 Go 安装、内置 UI、独立 REST/MCP 和双副本检查必须通过。
6. 从标签创建包含 `LICENSE`、`NOTICE` 和 `THIRD_PARTY_NOTICES.md` 的源码包，生成基于文件名的校验和；上传到草稿 GitHub Release 后，在新目录中重新下载验证。只有发布记录和限制准确时才可公开。
