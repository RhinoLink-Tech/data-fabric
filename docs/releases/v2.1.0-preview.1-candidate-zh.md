# Data Fabric v2.1.0-preview.1 候选评审

**状态：** 维护者已批准的 Preview 候选评审。本文档本身不会发布产物；当前发布状态以对应 GitHub Release 和 issue #442 为准。
**批准渠道：** Preview 预览版，linux/amd64 容器镜像及 GitHub 源码压缩包。
**最近已发布稳定版本：** v2.0.0（2026-10-21）。
**版本决策：** 维护者于 2026-11-09 确认使用 v2.1.0-preview.1，以及 linux/amd64、单机 MySQL 元数据库与示例源的 Preview profile。采用者和任务假设仍未验证。

## 预览版用于什么

评估一条自托管只读网关路径：登记一个获准的 MySQL 数据源，再由一个 REST 应用和一个远程 MCP 应用复用同一策略。样例数据是合成数据。本版本不宣称外部团队已经验证产品定位，不宣称真实模型业务任务已成功，也不宣称组织愿意付费。 #456 的真实模型任务评估和 #459 的付费方案验证仍未完成；本 Preview 不能作为模型效果、团队持续使用或付费意愿的证据。

目标团队、操作角色、重复任务、对比方法和成功规则仍是[首个采用者画像](../product/first-adopter-profile.md)中的假设。本次确认只覆盖版本和技术 Preview 范围；参与者招募和外部评估仍未完成。不得把用户价值、模型效果、团队采用或付费意愿写成已验证结论。

## 候选版本内容

- 新增仅由 tag 触发的 linux/amd64 GHCR 镜像发布流程，可通过 digest 固定的 Compose overlay 安装。运行镜像包含 SQLGlot、项目 notices，以及为 server 和 replica-ingress 二进制实际导入模块生成的确定性许可证材料清单。
- onboarding 工具可安全初始化密钥和本地 TLS 文件、生成有时限的管理 token，并诊断当前部署；不会通过重置数据来“修复”问题。
- 当前 profile 的操作手册可以校验加密备份，并准备恢复到全新的 Compose 项目。
- 查询准入、活跃流数量、租户准入、连接池和结果预算给出更明确的边界。这些限制按进程生效，不提供集群级配额，也不构成主机内存保证。
- MCP 调用方可选择文档支持的分页或流式行为。REST/MCP 验收记录覆盖候选版本续页、策略变更、拒绝访问和生命周期结果。
- 新增 provider-neutral Agent Skill，说明如何按 schema 执行只读查询并限制结果规模。
- UUID 类型现在会拒绝格式错误的字符串和字节切片。

完整变更见[未发布变更记录](../../CHANGELOG.md)。

## 评估 profile

| 方面 | Preview 范围 |
| --- | --- |
| 平台与拓扑 | 单台 linux/amd64 主机；Docker Engine 24+ 和 Docker Compose plugin 2.24+。Compose 会启动 MySQL 元数据库、合成 MySQL 示例源、一个 API 进程和一个远程 MCP 进程。不提供 HA 或自动故障切换。 |
| 数据库 | 默认 Compose profile 将元数据库和示例源固定到 MySQL 8.4.13 及其镜像 digest。精确镜像引用见 deploy/mcp/docker-compose.yml。首个任务 profile 是一个 MySQL 8.4.13 数据源，并使用权限受限的只读账号。 |
| 身份 | REST 管理使用配置好的短时 Data Fabric bearer token。远程 MCP 要求外部 OIDC provider、TLS、已配置的 issuer、audience 和查询 scope。项目不负责运行身份提供方。 |
| 网络 | 推荐 Compose profile 中，管理 API 仅绑定 loopback。远程 MCP 只通过配置好的 TLS endpoint 暴露。 |
| 主机工具 | 初始化和诊断使用 Python 3 标准库及 OpenSSL。采用发布镜像时不需要 Go、源码编译或手动安装 Python 第三方包。 |
| 查询行为 | 只读操作。按数据源支持目录和 SQL 兼容文档确认具体版本及操作证据。数据源已注册不代表它自动成为生产级验证连接器。 |
| 支持 | 社区维护，通过 GitHub Discussions 和 issue 表单尽力协助；没有响应时限 SLA，也没有旧版本支持期限承诺。 |

## 资源与行为限制

测量过的首个 profile 默认允许每个 API 或 MCP 进程最多 4 个活跃查询或流，其中每个经过验证的 tenant 在该进程中最多 2 个。每个数据源、每个进程的默认 SQL 连接池最多打开 10 个连接。单个查询的返回结果预算为 64 MiB。

这些是准入和输出限制，不会限制源引擎扫描量、进程总 heap、CPU 或多个副本的总用量。返回结果预算不等于内存包络或生产容量承诺。详见[当前运行限制](../roadmap.md#current-operating-limits)和[查询可观测性说明](../observability.md#current-query-and-cursor-capacity)。

续页 cursor 保存在所属进程的内存中。重启该进程会丢失进行中的 continuation 状态。该 profile 不提供共享 cursor 存储、副本故障切换或集群级租户配额。必须持久化 credential keyring，并遵循备份恢复手册；恢复过程不会恢复实时查询 cursor。

SQL 能力仍是文档说明的只读子集。本 Preview 不覆盖跨源 join、写操作、通用 SQL 兼容、数据脱敏、任意列级策略，也不表示目录中的所有连接器都已达到生产就绪。

## 升级与恢复

最近的稳定版本是 v2.0.0。现有[升级指南](../upgrading-v1.2.0.md)覆盖 v1.2.0 到 v2.0.0；它不能作为 v2.0.0 升级到 Preview 的验证证据。

本 Preview 应部署到全新、隔离的 Compose 项目，并使用合成数据或明确获准的数据。不要让 Preview 镜像连接现有生产元数据库 volume。目前没有承诺支持从 v2.0.0 原地升级，也没有承诺 Preview 到未来 Stable 版本的迁移。请把预览数据视为评估数据；更换候选版本前先保留并验证备份。[备份与恢复手册](../operations/mcp-profile-backup-recovery-zh.md)绑定候选源码 revision，并恢复到新的项目。
