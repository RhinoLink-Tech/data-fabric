# Data Fabric v2.1.0-preview.2 candidate and risk record

**Channel:** developer Preview. The latest stable release remains v2.0.0. This document describes the proposed scope and the checks required before publication; the matching GitHub Release records the final source SHA, image digest, archive checksum, and actual acceptance results.

**Preparation baseline:** master `4e4a06a28258fba351998e23fd29309e7113783e` on 2026-11-16. The release-preparation merge changes the source revision; all artifact and CI evidence must refer to the final tagged commit, not this baseline.

## Supported evaluation profile

One self-hosted `linux/amd64` host using the documented Compose profile, MySQL 8.4 metadata and synthetic MySQL sample data, REST management, and remote MCP with a correctly configured external OIDC issuer and trusted TLS. The published image bundles its pinned SQL translation runtime and license materials. Select other data sources only within the versions, operations and verification evidence recorded in the [support catalog](../data-source-support.md).

This is an evaluation release, not a production-readiness, high-availability, automatic-failover, support-window, performance-SLA, universal SQL or cross-connector compatibility promise. The tested single-host profile does not establish cluster-wide query budgets or cursor failover. Deployment time and resource usage depend on the host and workload; do not copy measurements from an earlier candidate as results for this image.

The public WorkBuddy service's self-service registration, independent first-use journey and generic-client automatic OAuth onboarding are not included in this release's supported profile. Optional browser source onboarding, source update, self-service provisioning and related identity flows are experimental, opt-in, and require their own isolation, identity, network and client validation. They are not evidence of marketplace publication or production readiness.

The source-archive recovery allowlist currently recognizes preview.1, not the new preview.2 archive. Do not advertise no-Git archive backup for preview.2. Do not promise an in-place upgrade or rollback from preview.1 or v2.0.0: use a separate evaluation project and fresh volumes. Preserve existing deployments and keys. An independently validated backup and restore procedure is required before using valuable data.

## Artifact and acceptance gates

1. Merge the release-preparation PR, freeze its exact master commit, and require a successful master push CI for that commit, including contract selection, unit/build, PostgreSQL/MySQL contracts, and public REST/MCP acceptance.
2. Run the applicable full candidate checks, including formatting, `go vet`, `go test`, `go build`, image and license checks. Record actual run links and do not treat skipped jobs as passed.
3. Verify that the version tag and the version/source image tags are unused, then create an annotated `v2.1.0-preview.2` tag at the exact approved master commit. The tag workflow must build and publish the image with SBOM and provenance.
4. Record the real public image `tag@sha256`, source revision and platform. Dispatch the published-image acceptance workflow against that exact digest; it must pass the documented no-Go install, UI, REST/MCP and two-replica checks. These checks use Git and do not by themselves prove a no-Git archive installation.
5. Create the source archive from that tag, include `LICENSE`, `NOTICE` and `THIRD_PARTY_NOTICES.md`, generate a portable basename checksum, upload both to a draft Release, and verify the downloaded pair in a new directory. Publish only after the evidence and known limitations are accurate; repeat the download check after publication.

The [English](v2.1.0-preview.2-install.md) and [Chinese](v2.1.0-preview.2-install-zh.md) guides explain the selected installation and limits. The published digest and source-archive checksum must be obtained from the matching release record; they are intentionally not invented in this source document.
