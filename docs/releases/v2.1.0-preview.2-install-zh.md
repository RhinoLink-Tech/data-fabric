# 安装 v2.1.0-preview.2 发布镜像

[English](v2.1.0-preview.2-install.md) · [版本下载与精确镜像 digest](https://github.com/RhinoLink-Tech/data-fabric/releases/tag/v2.1.0-preview.2) · [预览范围与风险](v2.1.0-preview.2-candidate.md)

本指南适用于 Release 页面和不可变镜像 digest 已发布后的 `v2.1.0-preview.2`。它在一台 `linux/amd64` 主机上运行带合成 MySQL 示例数据的评估配置，不承诺生产可用性、高可用或 SLA。

需要 Docker Engine 24+、Docker Compose 2.24+、Python 3、OpenSSL、`curl`、`tar` 和 `sha256sum`。远程 MCP 还需要 HTTPS OIDC 身份提供方、正确配置的 audience，以及包含所需 `data-fabric.query` scope 的 access token。镜像部署不需要 Go 编译器或宿主机 Python 第三方包。请使用新的隔离 Compose 项目，以及合成数据或明确获准的数据。

## 1. 下载并校验发布文件

先在 Release 页面核对源码包 SHA-256，再在新的空目录执行：

```bash
VERSION=v2.1.0-preview.2
ARCHIVE="data-fabric-${VERSION}-source.tar.gz"
BASE="https://github.com/RhinoLink-Tech/data-fabric/releases/download/${VERSION}"
curl -fL -o "$ARCHIVE" "$BASE/$ARCHIVE"
curl -fL -o "$ARCHIVE.sha256" "$BASE/$ARCHIVE.sha256"
sha256sum -c "$ARCHIVE.sha256"
tar -xzf "$ARCHIVE"
cd "data-fabric-${VERSION}/deploy/mcp"
```

校验失败时停止。该校验针对下载的源码包，不是镜像；同时请将校验文件中的值与 Release 页面记录比较。不要使用尚未发布或未验证的产物。

## 2. 初始化并配置

选择其他安装未使用的 Compose 项目名，后续 shell 也使用同一名称：

```bash
export COMPOSE_PROJECT_NAME=data-fabric-preview2
python3 ../../scripts/mcp/onboard.py init --directory "$PWD"
```

保持 `.env` 权限为 `0600`，按身份提供方设置 `MCP_OIDC_ISSUER`、`MCP_OIDC_AUDIENCE` 和所需 scope。从对应 GitHub Release 复制**完整的 tag@sha256 镜像引用**，写入 `.env` 中唯一的未注释 `DATA_FABRIC_IMAGE` 条目。示例格式为 `ghcr.io/rhinolink-tech/data-fabric:v2.1.0-preview.2@sha256:<digest>`；占位符不能直接使用。

生成的 localhost 证书用于本地评估；远程访问需要适当的受信任证书。请妥善保存 `.env`、TLS 私钥和凭证密钥环：更换或丢失密钥环可能使已保存的数据源凭证无法解密。参见[部署指南](../mcp-deployment-zh.md#1-初始化本地配置)。

## 3. 启动并检查

```bash
docker compose -f docker-compose.yml -f docker-compose.release.yml pull
docker compose -f docker-compose.yml -f docker-compose.release.yml up -d
docker compose -f docker-compose.yml -f docker-compose.release.yml ps
python3 ../../scripts/mcp/onboard.py doctor --directory "$PWD"
```

等待服务健康。未认证的 MCP 探测返回 `401` 属于预期；完成授权查询仍需要可用的身份提供方及 access token。

## 4. 登记示例并查询

按照[身份与 token 配置](../mcp-deployment-zh.md#3-生成短时管理-token)、[示例数据源登记](../mcp-deployment-zh.md)和 [Agent Skill 指南](../agent-skill-zh.md)操作。管理身份应与 OIDC 的 subject 和 tenant 对齐。示例数据为合成数据；接入客户端时请核对文档中注明的功能限制。

## 升级与恢复边界

请使用新的隔离项目和数据卷；从 v2.0.0 或 preview.1 原地升级尚未验证。归档恢复工具的白名单目前识别 preview.1，不识别本版本源码包。备份还存在[#522](https://github.com/RhinoLink-Tech/data-fabric/issues/522) 所述运行密钥与磁盘配置可能不一致的问题。迁移有价值的数据前，请独立验证备份、恢复流程和保留的密钥；profile 备份不包含业务源数据库或进行中的游标。

公开 WorkBuddy 服务的自助账号开通和任意 MCP 客户端的自动 OAuth 接入不属于本 Preview 已支持范围，参见 [#603](https://github.com/RhinoLink-Tech/data-fabric/issues/603) 和 [#608](https://github.com/RhinoLink-Tech/data-fabric/issues/608)。
