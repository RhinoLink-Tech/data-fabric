# v2.0.0 Core Release Candidate Review

**Status:** Preparation record only. No v2.0.0 tag or stable GitHub Release has been created.

## Version and scope decision

The next core release should target **v2.0.0**. Since v1.2.0, the gateway changed authentication requirements, data-source ownership, and name uniqueness in ways that require deployment changes. A patch or minor version would understate these compatibility changes.

The only published starting release is v1.2.0. The security-maintenance candidate discussed in #206 is a separate candidate and is not a published v1.2.1 release. This core candidate must be validated and recorded independently.

The exact candidate commit, downloadable source archive checksum, and final validation links are recorded in [issue #211](https://github.com/RhinoLink-Tech/data-fabric/issues/211) after the final documentation commit and checks.

## Compatibility changes users must plan for

- **Configuration file:** configs/config.yaml is no longer tracked. Back it up securely before upgrading and recreate local configuration from configs/config.yaml.example; the example contains placeholders.
- **JWT secret:** HTTP startup requires a non-placeholder secret of at least 32 bytes. There is no built-in default. SECURITY_JWT_SECRET is canonical; JWT_SECRET remains a compatibility alias.
- **Fetch authentication:** Both initial and continuation /api/v1/fetch requests require a Bearer token even when security.enable_auth is false. Release mode also requires security.enable_auth: true.
- **Data-source ownership:** New rows are assigned to the authenticated caller and tenant. Legacy rows without ownership metadata are visible only to administrators; ownership is not guessed or silently assigned.
- **Name uniqueness:** Names are unique per tenant instead of globally. The migration replaces the old global uniqueness index.
- **Credential encryption:** The HTTP and MCP servers require a persistent credential keyring. Keep existing key material across restarts and migration; losing it makes stored credentials unreadable.
- **Toolchain:** The source requires Go 1.26.1.

Detailed steps are in [Upgrading from v1.2.0](../upgrading-v1.2.0.md).

## Release gates and known limits

| Gate | Current status | Release handling |
| --- | --- | --- |
| Historical credential exposure, #12 | Open P0; external credential rotation has not been confirmed. | **Blocking.** Do not publish a stable release until affected credentials are rotated or revoked and the issue is resolved. This document does not repeat credential values. |
| SQL dialect translation runtime, #212 | The API and README advertise translation; the runtime image contains the Go binary but not Python, while the external translator invokes Python. | **Blocking while translation is part of the release.** Package and constrain the runtime, or explicitly remove/disable the capability before freezing the candidate. |
| Remote MCP enterprise token validation, #217 | Open P1; OIDC/JWKS access-token validation is not implemented. | Security review must decide whether the documented HS256 token boundary is acceptable for this release. Do not claim native OIDC validation. |
| Table-level authorization, #218 | Open P1; authorization is at the data-source level, not per schema/table. | Security review must decide whether the current data-source boundary is sufficient. Document this limitation and do not claim table-level policy enforcement. |
| Column-level policy, #219 | Open P2 and depends on #218. | Not implemented; no column-level authorization claim. |
| Live Trino coordinator verification, #179 | Deferred by the maintainer; protocol-level tests use a simulated coordinator. | Keep this as a stated limitation; do not claim live Trino/Presto/OpenLooKeng validation. |
| Full connector contract matrix, #35 | Open P2. | The table above is a registry inventory, not a claim of uniform live verification. |

A successful CI run does not close an external credential-rotation task or substitute for a security scope decision. Keep the candidate unpublished while a required release gate is open.
