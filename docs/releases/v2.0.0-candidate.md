## Version and scope decision

The next core release should target **v2.0.0**. Since v1.2.0, authentication requirements, data-source ownership, and name uniqueness changed in ways that require deployment changes. A patch or minor version would understate these compatibility changes.

The latest published stable release is v1.2.0. This candidate verifies upgrades from v1.2.0 only; earlier versions need a separate rehearsal. The security-maintenance candidate discussed in #206 is separate and is not a published v1.2.1 release.

## Registered source matrix

The per-connector matrix is maintained in the generated [Data Source Support Catalog](../data-source-support.md), and GET /api/v1/database/types uses the same runtime catalog. A registered type means code is present, not that every version or operation has been verified. The catalog records end-to-end status, version evidence, operations, capabilities, and limitations.

For release wording, recommend only connector operations marked end-to-end verified. Other entries are implementation-present or experimental and must not be presented as verified production support. The contract suite in #35 remains open for broader, versioned live verification.

Apache Ozone is not registered. Remaining client stubs are placeholders; see [Ozone support status](../ozone-support.md). Trino/Presto/OpenLooKeng routing has simulated-coordinator coverage; live coordinator verification remains deferred by #179.

## Compatibility changes users must plan for

- **Configuration file:** configs/config.yaml is no longer tracked. Back it up securely before upgrading and recreate local configuration from configs/config.yaml.example; the example contains placeholders.
- **JWT secret:** HTTP startup requires a non-placeholder secret of at least 32 bytes. There is no built-in default. SECURITY_JWT_SECRET is canonical; JWT_SECRET remains a compatibility alias.
- **Fetch authentication:** Both initial and continuation /api/v1/fetch requests require a Bearer token even when security.enable_auth is false. Release mode also requires security.enable_auth: true.
- **Data-source ownership:** New rows are assigned to the authenticated caller and tenant. Legacy rows without ownership metadata are visible only to administrators; ownership is not guessed or silently assigned.
- **Name uniqueness:** Names are unique per tenant instead of globally. The migration replaces the old global uniqueness index.
- **Credential encryption:** The HTTP and MCP servers require a persistent credential keyring. Keep existing key material across restarts and migration; losing it makes stored credentials unreadable.
- **Toolchain:** The source requires Go 1.26.1.

Detailed steps are in [Upgrading from v1.2.0](../upgrading-v1.2.0.md).

### Open P1 scope and risk decisions

These issues remain open and are not being represented as completed. The decisions below limit the claims and intended deployment scope of this candidate; they do not close the underlying roadmap work.

| Issue | Candidate scope decision | Accepted risk and required wording |
| --- | --- | --- |
| #15 SQL and non-SQL execution contracts | The candidate supports only the connector operations explicitly listed in the source catalog. | There is no universal query executor across SQL, object/file, and native API sources. Treat non-SQL connectors as experimental or implementation-present unless their catalog entry has end-to-end evidence. |
| #28 Multi-replica query sessions | The v2.0.0 deployment scope is a single gateway instance for streaming and paginated continuation. | Query sessions are in process memory and are not shared across replicas or restarts. The API guide already states this limit; do not recommend multi-replica streaming until shared or stateless continuation is implemented and tested. |
| #114 Iceberg query execution | Iceberg query execution remains Phase 2 and is outside the v2.0.0 verified connector scope. | The current Iceberg query method is unimplemented. Keep it marked experimental/unverified and do not claim Iceberg table reads. |

The release workflow requires a written decision for every open P1 treated as non-blocking. The narrow scope and user-facing limitations above are the candidate's risk decisions. #12 is resolved; before publication, record the exact documentation-complete commit, source archive checksum, final CI, and upgrade evidence in #211.
