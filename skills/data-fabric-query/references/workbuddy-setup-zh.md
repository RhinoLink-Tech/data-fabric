# WorkBuddy 接入 Data Fabric

连接器和 Skill 需要连接用户或团队自己的 Data Fabric 服务；安装 Skill 不会自动部署服务或创建数据源。用户可连接有权限使用的既有服务，也可由管理员在自己的网络中部署服务，再通过服务连接云端或本地数据库。

## 管理员准备

1. 按 [MCP 中文部署指南](https://github.com/RhinoLink-Tech/data-fabric/blob/master/docs/mcp-deployment-zh.md)部署服务，并提供 WorkBuddy 客户端能访问的 HTTPS MCP 地址（包括端口及路径，如有）。客户端必须信任服务证书；MCP 服务也必须能访问目标数据库。客户端中的 localhost 指客户端运行环境，不一定是数据库所在电脑。
2. 通过 Data Fabric 管理界面或管理员安全配置数据源、启用它，并授予使用者对应身份和读取权限。不要在聊天中输入数据库密码。
3. 根据服务身份配置，提供身份提供方签发的 MCP 访问令牌；管理 API 的 JWT 不可替代。不同部署的 issuer、audience、scope 须符合服务设置。令牌过期后重新获取并更新连接器。

## 用户连接

在 WorkBuddy 安装 Data Fabric 连接器并启用；如果使用独立 Skill，仍需另行配置 MCP 连接。连接表单填写服务的域名、可选端口和 MCP 路径，不含 https://（例如 data-fabric.example.com/mcp），再填写管理员提供的 MCP 访问令牌。不要把令牌放在聊天或截图中。确认信任后，检查 Data Fabric 工具是否出现。

可以从以下请求开始：

- “列出我有权限访问的数据源。”
- “查看订单表字段，统计本月订单数量。”
- “查询最近的订单，需要时获取后续结果。”

数据源列表为空时，先请管理员核对服务环境、数据源状态、身份和授权。连接失败时，核对地址、网络、证书和令牌是否有效；不要绕过证书验证。

## 服务版本和数据源管理

已发布的 v2.1.0-preview.1 镜像提供已配置数据源的发现和只读查询。类型发现与已有数据源管理是在该预览版本之后合入主线的功能，必须部署包含相应工具的服务，并在 WorkBuddy 的工具列表中确认存在；不能假定旧镜像具备它们。

新服务支持时，可以询问“当前服务支持哪些数据库和文件格式？”；注册类型不代表已配置数据源或所有版本均已验证。具有所需管理 scope 和所有权或管理员权限的用户可以请求重命名、启用、停用或测试已有数据源。连接测试仅支持非 TLS 的 MySQL 和 PostgreSQL，PostgreSQL 还受服务端系统环境限制。删除是永久操作，必须先明确确认具体数据源名称与 ID，服务端还要求租户与所有权匹配。

这些 MCP 工具不提供新建数据源、修改连接设置或管理凭据；请通过管理界面或管理员完成安全配置。不要向助手提供密码或访问令牌。
