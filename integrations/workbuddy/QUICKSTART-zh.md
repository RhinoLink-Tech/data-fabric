# 在 WorkBuddy 中开始使用 Data Fabric

这份指南面向已经部署 Data Fabric 的团队。管理员先准备一次自部署服务和身份；每位使用者将 WorkBuddy 连接到该服务，然后发现、查询或管理被授权的数据源。在线体验是另一个连接器，请根据实际使用的服务选择。

## 管理员准备一次

1. 按[中文部署指南](../../docs/mcp-deployment-zh.md)启动 Data Fabric。记下 WorkBuddy 可访问的 HTTPS MCP 地址（以 `/mcp` 结尾），并确认客户端信任证书。发布的 Preview 为单机体验配置，具体前提和范围见部署指南。
2. 在管理 API 的 `/ui/` 页面添加并测试数据源，启用数据源，并按实际需要配置使用者的身份、租户和读取权限。管理 API 的访问地址以部署配置为准，不能假设与 MCP 端口相同。使用合成数据试用时，参考[示例订单验收](../../docs/agent-skill-zh.md#用合成订单验收)。
3. 从配置的身份提供方为使用者获取符合服务 issuer、audience 和 scope 要求的 MCP 访问令牌。管理 API 的 JWT 与 MCP 访问令牌不能互换。

## 使用者连接并提问

连接器的市场状态以 WorkBuddy 平台实际显示为准；也可按[客户端接入指南](../../docs/agent-skill-zh.md#workbuddy)导入 Skill 并配置自定义连接器。优先使用客户端支持的 OAuth 登录；连接方式以实际客户端版本为准。不要把令牌或数据库密码写进聊天消息。

连接并启用后，在 WorkBuddy 会话中输入：

> 使用 Data Fabric，列出我可以访问的数据源，找到订单表并查看字段。然后查询最近的订单，按需获取后续结果。

当已连接服务提供类型发现工具时，也可以问：

> Data Fabric 当前支持哪些数据库、对象存储和文件格式？请按分类说明，并标明已验证的版本。

类型发现列出服务当前构建中注册的连接器，不代表已配置或所有版本均已验证。受限候选服务分别返回实例类型策略和向导类型策略标记，但不保证连接、授权或版本兼容。旧版服务可能没有该工具；此时请查看版本对应的支持目录。

先检查连接器是否可用；如果看不到数据源，请管理员核对来源是否启用、用户身份和授权。如果连接失败，核对 MCP 地址、网络、证书信任以及令牌有效期和范围。失败时不要绕过证书检查。

## 上架后的目标体验

管理员仍需准备 Data Fabric 服务、身份和数据源。用户在 WorkBuddy 市场安装连接器，在连接表单中填写服务域名、端口和路径（不带 `https://`）以及 MCP 访问令牌，再开始提问。本仓库的连接器包为候选，市场状态以平台实际显示为准；市场导入及本机连接、查询的完整流程需分别验证。

更多能力和 API 用法见[项目首页](../../README_zh.md)及[API 使用指南](../../docs/api_usage.md)。

## 连接自己的数据源

本连接器需要可由 WorkBuddy 访问的 Data Fabric MCP 服务。用户可以在自己网络中部署 Data Fabric 镜像并配置数据库，或连接其有权限使用的已有服务。MCP 与数据库之间要具备网络连通性；WorkBuddy 中的 `localhost` 指连接器实际运行环境，不一定是用户电脑。按部署环境配置 HTTPS、身份认证和网络访问，避免将数据库端口直接开放。演示地址只使用合成数据，不是用户自己的数据源。

已发布的 v2.1.0-preview.2 包含数据源类型发现、已授权的数据源管理，以及默认关闭的实验性浏览器接入与更新工具；是否可用还取决于服务配置、权限和客户端实际发现的工具。较早的 preview.1 不包含这些后来加入的能力。

- **了解支持范围**：询问“当前服务支持哪些数据库和文件格式？”；进一步询问指定类型时，助手会读取该类型的验证情况和限制。
- **管理已有数据源**：在具有 data-fabric.sources.manage 和所需所有权或管理员权限时，可要求重命名、启用或停用；更改前核对数据源和目标状态。
- **测试连接**：可测试已配置的 MySQL 或 PostgreSQL 数据源；较新源码构建在启用受限策略后还支持 MariaDB。普通部署仅支持非 TLS；启用受限向导的候选服务可测试验证证书的 TLS 连接。
- **删除**：明确确认数据源名称和 ID 后才执行；该操作永久删除，服务端还要求对应租户和所有权。

**安全新增（实验功能）**：preview.2 包含默认关闭的浏览器接入工具，仍需实际 WorkBuddy 客户端端到端验收。管理员部署并启用后，确认客户端实际发现 `begin_data_source_onboarding` 和 `get_data_source_onboarding_status`，再请助手启动向导。打开返回的链接，用与 MCP 相同的 issuer、用户和租户登录，在浏览器安全填写连接信息、测试并保存，回到会话告知助手，再由助手读取真实状态。链接本身不授予权限。默认支持服务允许的 IPv4 地址和端口上的 PostgreSQL/MySQL；更新后的源码构建可分别开启实验性的 MariaDB 和 openGauss，后者要求校验证书的 TLS，实验 Core 构建不含其驱动。它们尚未包含在 preview.2 镜像中。向导还需要 OIDC、管理 scope 和服务端身份授权。如部署显式开启 `DATA_FABRIC_WORKBUDDY_SOURCE_UPDATES=true` 且实际发现更新工具，也可在浏览器中更新服务允许的已有数据源连接与凭据；以部署策略和工具实际返回为准。

如工具缺失、权限或连接失败，请管理员核对版本、授权和网络策略，或通过管理 UI 安全配置。切勿在聊天中发送密码或令牌。部署后应以实际服务和工具列表为准。

## 可选：为自部署连接获取短期令牌（实验性）

如果管理员的 OIDC 身份服务支持公开客户端的授权码与 PKCE，可使用仓库中的实验性辅助工具在本机登录后获取访问令牌。**它不是自动授权或自动续期方案**；令牌过期后需重新执行并更新客户端。该工具已用 Keycloak 和合成数据验证 MCP 只读查询，但手动令牌接入真实 WorkBuddy 的完整流程尚未验证。

管理员需先注册一个不使用 client secret 的公开客户端，启用授权码和 S256 PKCE，并将精确回调 `http://127.0.0.1:8765/callback` 加入允许列表；配置 Data Fabric 所需 issuer、audience、用户租户和相应授权。客户端 ID、端口及范围必须以管理员配置为准；正式服务现有的浏览器客户端不能默认用于此回调。

在运行 WorkBuddy 的用户所能操作的电脑上，使用受信任的终端运行（按管理员提供的信息替换示例值）：

```sh
python3 scripts/mcp/workbuddy_token.py \
  --issuer https://identity.example.com/realms/team \
  --client-id data-fabric-user \
  --port 8765
```

按浏览器提示完成登录后，工具会要求你确认，再将 access token 显示在终端。仅当客户端提供受保护的 Bearer 凭据输入方式时，才手动使用令牌；优先使用客户端自带 OAuth。WorkBuddy 5.11.3 的自定义 MCP 使用 JSON 文件，直接写入令牌会持久化敏感信息，不要将令牌写入持久配置或聊天。工具不会写入令牌文件，也不会显示或保存 refresh token。请确保终端没有被记录或共享，勿将令牌发送到聊天或日志；终端可能保留显示内容，使用后按终端自身方法清除。令牌过期后重新运行并更新连接。需要管理操作时，管理员必须授予管理权限，并按需传入 `--scope 'openid data-fabric.query data-fabric.sources.manage'`；如果身份服务需要 OAuth resource 参数，还需提供 `--resource`。客户端注册、audience、scope 和数据库权限最终由身份服务与 Data Fabric 网关校验，此辅助工具不验证访问令牌签名，也不授予额外权限。
